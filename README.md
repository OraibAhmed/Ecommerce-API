مشروع سيرفر (Backend REST API) لمتجر إلكتروني. فكرته ببساطة إنه يربط الموقع بالمركزيّة (قاعدة البيانات السحابية Neon PostgreSQL) عشان ندير أجهزة المتجر من: منتجات، فئات، ومستخدمين.

المشروع مبني بـ Node.js و Express، ومختبر بالكامل وما فيه أي بيانات وهمية (Mock Data) — كله شغال على قاعدة بيانات حقيقية بالكامل!

🛠️ الأقسام الرئيسية في السيرفر
عندنا 3 أجزاء أساسية نقدر نتحكم فيها:

📦 المنتجات (Products): عرض، إضافة منتج جديد، تعديل بياناته، أو إيقافه/تعطيله (Soft Delete بدون ما نحذفه نهائياً من الداتابيز).

📂 الفئات (Categories): عرض الفئات (مثل: إلكترونيات، ألعاب...)، إضافة فئة جديدة، أو تعديلها.

👥 المستخدمين (Users): عرض المستخدمين، إضافة مستخدم، أو تفعيل وتجميد حسابه.

💻 الأدوات والتقنيات المستخدمة
Node.js & Express: عشان نبني السيرفر والروابط (Routes).

Neon PostgreSQL: قاعدة البيانات السحابية (على السحاب، مو على الجهاز).

pg (node-postgres): المكتبة اللي بتخلي Node.js يحكي مع قاعدة البيانات.

Postman: برنامج لاختبار الـ API وتأكيد إن الأوامر شغال تمام.

لوحة اختبار (Test Dashboard): صفحة ويب بسيطة ومدمجة بـ HTML/JS عشان نجرب نرسل طلبات ونشوف النتيجة من المتصفح مباشرة.

🚀 كيف تشغل المشروع عندك؟
إذا أخذت الكود على جهازك، اتبع الأرقام هي بس:

نزل الحزم (Packages):

Bash
npm install
سوي ملف البيئة (.env):
انسخ ملف .env.example وسمه .env وحط فيه رابط الاتصال بقاعدة بيانات Neon الخاصة فيك.

شغل السيرفر (وضع التطوير):

Bash
npm run dev
راح يشتغل السيرفر على الرابط: http://localhost:3000

📡 الروابط الرئيسية (Endpoints)
الرابط الأساسي لجميع العمليات هو: http://localhost:3000/api

1. المنتجات (/api/products)
GET /api/products 👈 عرض كل المنتجات.

GET /api/products/:id 👈 عرض منتج معُيّن برقمه.

POST /api/products 👈 إضافة منتج جديد (يجب إرسال الاسم، السعر، الـ SKU، إلخ).

PUT /api/products/:id 👈 تعديل بيانات منتج كاملة.

PATCH /api/products/:id/deactivate 👈 تعطيل منتج.

2. الفئات (/api/categories)
GET /api/categories 👈 عرض الفئات.

POST /api/categories 👈 إضافة فئة جديدة.

PUT /api/categories/:id 👈 تعديل فئة.

3. المستخدمين (/api/users)
GET /api/users 👈 عرض المستخدمين.

POST /api/users 👈 إضافة مستخدم جديد (اسم، إيميل، كلمة سر).

PATCH /api/users/:id/status 👈 تغيير حالة حساب المستخدم (تفعيل/تعطيل).

🚥 إجابات السيرفر (Status Codes)
السيرفر برد عليك دائماً بكود يوضح شو صار مع طلبك:

200 OK: كل شيء تمام والعملية نجحت 👍

201 Created: تم إضافة عنصر جديد بنجاح 🎉

400 Bad Request: في مشكلة ببياناتك (مثلاً: ناسي تكتب اسم المنتج، أو حاط السعر بالسالب) ❌

404 Not Found: الشيء اللي بتدور عليه مش موجود 🔍

409 Conflict: البيانات مكررة (مثلاً: الإيميل أو كود الـ SKU مستخدمين من قبل) ⚠️

500 Internal Server Error: مشكلة غير متوقعة بالسيرفر نفسه 💥

اختبرنا السيرفر بـ 16 حالة اختبار مختلفة لتغطية كل الاحتمالات (النجاح والأخطاء):

لوحة اختبار بالمتصفح: بتفتح http://localhost:3000 وبتقدر تضغط أزرار تجريبية وترسل طلبات مباشرة، وفي زر بيعمل تجربة شاملة وبيعطيك (Passed ✅).

ملفات Postman: مرفق مع المشروع ملفين بالـ Postman جاهزين لتشغيل الـ 16 اختبار دفعة واحدة، والنتيجة ناجحة 100% (16/16 Passed).

🛡️ الحماية والأمان في المشروع
ممنوع SQL Injection: كل الاستعلامات تستخدم نظام البرامترات المجهزة ($1, $2) لحماية القاعدة من الاختراق.

التحقق من البيانات: السيرفر برفض الأسعار أو أعداد المخزون السالبة تلقائياً.

Soft Delete: لما نعطل منتج ما بنحذفه كلياً من قاعدة البيانات عشان ما نخرب تاريخ الطلبات القديمة.

إخفاء الأسرار: كلمة سر قاعدة البيانات مأمنة بملف .env وما بتترفع على GitHub أبداً.
