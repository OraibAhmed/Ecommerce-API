# 🛒 Ecommerce API (Backend)

هذا المشروع عبارة عن **Backend REST API** لمتجر إلكتروني. فكرته إنه يربط الموقع مع قاعدة البيانات السحابية **Neon PostgreSQL** حتى نقدر ندير بيانات المتجر مثل المنتجات، الفئات، والمستخدمين.

المشروع معمول باستخدام **Node.js** و **Express**، وكل البيانات الموجودة فيه حقيقية ومتصلة بقاعدة البيانات، يعني **ما فيه أي Mock Data**.

---

# 🛠️ شو بقدر أعمل بالمشروع؟

## 📦 المنتجات (Products)

* عرض جميع المنتجات.
* عرض منتج معين.
* إضافة منتج جديد.
* تعديل بيانات المنتج.
* تعطيل المنتج (**Soft Delete**) بدون حذفه نهائياً من قاعدة البيانات.

## 📂 الفئات (Categories)

* عرض جميع الفئات.
* إضافة فئة جديدة.
* تعديل بيانات الفئة.

## 👥 المستخدمين (Users)

* عرض المستخدمين.
* إضافة مستخدم جديد.
* تفعيل أو تعطيل حساب المستخدم.

---

# 💻 التقنيات المستخدمة

* **Node.js**
* **Express.js**
* **Neon PostgreSQL**
* **pg (node-postgres)**
* **Postman**
* **HTML + JavaScript Test Dashboard** لتجربة الـ API مباشرة من المتصفح.

---

# 🚀 تشغيل المشروع

1. نزل المكتبات:

```bash
npm install
```

2. اعمل ملف **.env**:

* انسخ ملف `.env.example`.
* غير اسمه إلى `.env`.
* أضف رابط قاعدة بيانات **Neon PostgreSQL** الخاصة فيك.

3. شغل السيرفر:

```bash
npm run dev
```

بعدها رح يشتغل على:

```text
http://localhost:3000
```

# 📡 الـ API Endpoints

الرابط الأساسي:

```text
http://localhost:3000/api
```

## 📦 Products

```http
GET /api/products
```

عرض جميع المنتجات.

```http
GET /api/products/:id
```

عرض منتج حسب الـ ID.

```http
POST /api/products
```

إضافة منتج جديد.

```http
PUT /api/products/:id
```

تعديل بيانات منتج.

```http
PATCH /api/products/:id/deactivate
```

تعطيل المنتج.

# 🚥 Status Codes

* ✅ **200 OK** → العملية نجحت.
* 🎉 **201 Created** → تم إنشاء بيانات جديدة.
* ❌ **400 Bad Request** → البيانات المرسلة فيها خطأ.
* 🔍 **404 Not Found** → العنصر غير موجود.
* ⚠️ **409 Conflict** → البيانات مكررة (مثل الإيميل أو SKU).
* 💥 **500 Internal Server Error** → خطأ داخل السيرفر.

# 🛡️ الأمان بالمشروع

* حماية من **SQL Injection** باستخدام **Parameterized Queries** (`$1`, `$2` ...).
* التحقق من صحة البيانات مثل منع الأسعار أو كميات المخزون السالبة.
* استخدام **Soft Delete** حتى نحافظ على بيانات المنتجات وسجل الطلبات.
* بيانات الاتصال بقاعدة البيانات موجودة داخل ملف **.env** وما بتنرفع على GitHub.
